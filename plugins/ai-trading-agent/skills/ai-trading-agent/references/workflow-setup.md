# Assistant-operated setup on the current host

Setup is part of doing the user's research. The assistant chooses the relevant
workflow, checks actual local capability, prepares internal inputs, recovers from
bounded failures and delivers the answer. The user does not choose scripts,
write JSON or operate a workflow. Ask only for a material fact or permission
that available sources and standing instructions cannot supply.

Keep the complete portable skill folder on the chosen host. There is no backend,
localhost service, daemon, model API requirement or always-on process. Use the
host's permitted native tools and existing execution environment. Prefer free
primary evidence and supplied documents; paid providers and numerical libraries
are optional for the workflows that do not need them. Never install dependencies,
enroll in services, change subscriptions, connect accounts or modify permissions
as an incidental setup repair.

## Check the workflow you will actually use

When Python execution is permitted, the assistant runs `scripts/research_setup.py
check --workflow earnings_guidance --source SELECTED_FILE --output NEW_PRIVATE_DIR
--host CURRENT_HOST`. Paths are assistant-selected explicit files and a fresh
private directory outside the installed skill; a parent directory must already
exist. Use the actual interpreter available on the host. The other workflow names
are `event_research`, `refresh` and `options_activity`. These names select checks,
not an automatic interpretation of arbitrary prompts.

The helper calls existing `research_preflight.check()` for package integrity and
dependency inventory. It then checks workflow module imports/callable names,
reads/hashes only the explicitly selected source files and performs a real
write/read/remove probe in the explicit private output directory. It does not
scan folders, browser state, credentials, runtime configuration or accounts.
Imports are not successful calculations; module checks do not certify every
runtime branch. Missing optional libraries do not block an HTML/text supplied
source packet that uses only the standard library. A selected numerical operation
still needs its own required dependencies, actual invocation and retained output.

`--declare-native-tool NAME` records `DECLARED_NOT_TESTED`. A host name also remains
attributed. Neither a tool label, an import nor a retained model statement proves
browser, subscription, broker, independent-review or scheduling access. The
assistant must actually invoke an available native tool and retain its result
before describing that operation as observed. Report the operation and scope,
not a blanket claim that the host is supported or all hosts behave equivalently.

| Workflow | Local integration checked | Evidence the assistant still obtains |
| --- | --- | --- |
| Earnings/guidance | `research_session`, `filing_documents` | Actual current/prior release content, dimensions, cutoff, complete authored answer and review |
| Event research | Same session and document path | Actual announcement/agreement and requested event evidence; no invented closing probability |
| Refresh | `research_refresh` entry points | Pinned parent, unchanged/new/missing source decisions, genuinely newly opened evidence, successor answer/review |
| Options activity | `options_activity` parse/analyze/float binding | Explicit chain/flow/float originals with instrument, units, clocks, source coverage and unknowns |

`READY_FOR_LOCAL_EVIDENCE_PREPARATION` means only the package verified, selected
modules imported, explicit files were readable and this output probe succeeded.
It is neither a completed research answer nor a live acquisition claim. Source
authenticity, freshness, full question coverage and economic interpretation still
need host review. `LIMITED_SETUP` preserves concrete missing components and
recovery actions in `setup.json`; never relabel it a pass.

## Bounded recovery during the request

1. Read the actual failure and preserve its receipt, original request, original
   sources and first outputs. Recheck the relevant explicit path, operation
   inputs or native tool result; do not blindly rerun.
2. If a native source tool is absent or free access fails, use another already
   available permitted native source tool once, or use genuinely supplied
   documents. Respect host/browser/human-check policies. A search snippet is not
   the opened source. Without content, deliver a limited answer identifying the
   missing document and its consequence. Supplied old bytes cannot establish a
   current refresh.
3. If a numerical dependency/helper is absent, use an already available permitted
   Python environment once when appropriate. Otherwise continue supported source
   analysis and native review, explicitly identifying helper extraction,
   calculations or replay that were not performed. Do not silently replace a
   missing method with invented numbers. For inaccessible binary content, use
   an actually available native reader and retain its explicit readable
   projection with page/table locators, or mark the content unavailable.
4. Make at most one new setup attempt after an observed relevant change, in a
   fresh private directory. Preserve both attempts. If package integrity fails,
   obtain a complete verified package; do not rewrite the manifest to hide it.
   If output creation fails, report that inability and use a permitted private
   destination only when already available. Do not change access controls.
5. Continue the ordinary research/review workflow for supported work and deliver
   concrete remaining limitations. Setup never changes execution policy,
   account state, schedules or broker permissions.

The helper emits the bounded recovery plan; the host assistant performs any
permitted external fallback. It does not run hidden retries or contact providers.
The ordinary session's source/task binding and review cycle remain authoritative.

## Reproducible local and host exercise

The assistant can run `scripts/research_setup.py exercise --output NEW_PRIVATE_DIR
--host CURRENT_HOST`. This invokes the actual existing session start/packet and
filing-extraction route on a small fictional HTML release, retains hashes and
reports `LOCAL_SETUP_AND_PACKET_OBSERVED` only when extraction actually returned.
Package integrity remains separately visible even in an experimental candidate.
This fixture does not demonstrate a full answer/review, live access or another
host. It requires no network, account or additional provider. Every invocation
is on demand and exits when finished.

For a real host exercise, give that host the complete skill and use this compact
prompt in a fresh context, preserving the exact request and response privately:

> Using the installed AI Trading Agent skill, review this supplied fictional
> release's earnings and guidance and explain the main risks. Use only the
> supplied release, which states revenue of USD 110 million versus USD 100
> million, FY2030 adjusted diluted EPS guidance of USD 2.00 and possible supply
> delays. These fictional partial facts do not establish a current investment
> recommendation. Operate the setup and research workflow yourself. Retain the
> exact request/source and actual tool receipts. If an operation is unavailable,
> preserve the failure, try one permitted changed-input fallback, then deliver
> the supported answer with limitations. Do not browse, install, connect an
> account, start a service or trade. State whether Python helpers and independent
> native review actually ran; do not infer success from the host name.

Capture privately: `host`, `model_as_reported`, `observed_at`, `prompt_sha256`,
`source_sha256`, exact response path/hash, actual tool receipts with paths/hashes,
setup status, packet/review/delivery references when produced, failures/recovery,
and limitations. These are attributed captures, not authenticated host identity.
Use the existing `release_acceptance.compare_host_responses` contract and its
fixed fixture/catalog for cross-host acceptance comparisons; do not feed this
ordinary prose exercise into that strict fixed-response grader. An unrun host
stays `NOT_RUN`. A local Codex Windows run does not demonstrate Muse, Claude or
Instinct, and matching responses do not establish model equivalence. Keep private
captures outside the package. On installations requiring Sidechat for Muse,
use Sidechat and preserve the installation's isolation and cleanup rules.
