# Source-bound tax-lot comparison report

For a requested tax-aware sale comparison with supplied accounting records, use
`scripts/tax_lot_report.py` to generate the calculations and their visible
holding-period and retained-lot explanations together. Read the complete request
and source first. Keep their original UTF-8 text and SHA-256 hashes in the input;
do not replace the source with selected lots or inferred facts.

The invoked helper uses Python's standard library and the skill's accounting
kernels. It has no network, broker transport or persistent service. If the host
cannot execute it, disclose that limitation and perform the same scoped analysis
with available tools; do not claim a native generated receipt.

## Input contract

The JSON input contains exactly these fields:

- `schema_version`: `1`.
- `request`: `{text, sha256}` for the complete original request.
- `source`: `{id, text, sha256, adapter: "accounting_snapshot_v1"}`. The `text`
  contains the complete original accounting JSON object.
- `holding_period`: either `{convention: null, reason: "..."}` or
  `{convention: "illustrative_calendar_anniversary_more_than_one_year",
  assumption_label: "...", leap_day_policy: "unresolved"}`. The other explicit
  leap policies are `february_28` and `march_1`. Name the analytical assumption;
  it is not a jurisdiction default or a finding of legal tax status.
- `calendar`: `{timestamp_timezone: null}` for date-only data, or an explicit
  IANA timezone for aware timestamps. Naive timestamps are unsupported.
- `common_unit_assumption`: `null` when source units are fully scoped, otherwise
  an explicit explanatory string allowing common-unit analytical arithmetic.
- `alternatives`: a nonempty unique list drawn from `FIFO` and `HIFO`.

The supported original source has `sale` with `symbol`, `quantity`, `price`,
`date` and optional `specific_lots: [{id, quantity}]`; and the complete `tax_lots`
array with `id`, `symbol`, `acquired`, `quantity`, `unit_basis` and optional
`currency`. Supplied specific quantities are always evaluated exactly. Other
securities remain inventoried but are excluded from this security's selection.
FIFO orders calendar dates then lot identifiers; HIFO orders unit basis descending,
then calendar date and identifier. An aware timestamp is converted only in the
explicit calendar timezone; the report does not preserve intraday ordering.

Currency can be declared on the sale and each eligible lot, or by original
`monetary_scope: {currency: "USD", applies_to: ["sale", "tax_lots"]}` with the
actual source currency. Missing fields remain unspecified; conflicting currencies
reject arithmetic. Cash-ledger currency and unrelated fees never supply sale/lot
currency or sale charges. Amounts are gross before unprovided fees and adjustments.
Exact source JSON numeric lexemes and decimal strings are retained without float
conversion. No FX, tax-rate engine, after-tax optimization or forced winner exists.

Optional `outside_account_transactions` and `future_purchases` are arrays of
`{id, symbol, side, date, quantity}` with optional `lot_ref`. A linked acquisition
must match that known lot's security, acquisition calendar date and full original
quantity; it is not counted twice. Unlinked observations retain unknown lot
linkage. Unsupported mappings remain visible unresolved evidence. Missing/null
collections differ from supplied empty arrays; none proves complete external
coverage or that a future event actually executed. Do not rename arbitrary source
fields or infer a link to make this adapter fit; unsupported facts require a
separately scoped explanation or a reviewed adapter.

## Generate, verify and deliver

```text
python scripts/tax_lot_report.py compose report-input.json --output new-report
python scripts/tax_lot_report.py verify new-report --receipt-sha256 RECORDED_HASH
```

Compose requires a new output directory. It emits immutable `first-response.md`,
`response.json`, `summary.txt`, exact original source/request, input and a receipt.
Verification checks the exact inventory, dependency hashes and regenerated bytes.
Keep the receipt hash in the host's normal evidence capture. Preserve original
errors and failed invocations; a corrected run must use a new output directory.

Deliver the generated Markdown and retain the native JSON separately. If the
host or request requires a different response envelope, preserve every native
substantive proposal and its source/unit/assumption/limitation fields inside that
envelope, with the required host metadata. Retain and verify the original native
artifacts separately. An envelope is not byte-identical to the native projection;
this helper does not certify added prose or envelope completeness. Follow the
existing task output contract without changing it or adding private case fields
to this public helper.

Each proposal shows per-lot signed gains, calendar-based term categories and
separate signed term totals; a positive aggregate can still contain a loss lot.
It also shows original, selected and remaining quantities and joins those facts
to the conventional 30-calendar-day purchase flags. A fully sold acquisition is
not known retained shares. Flags do not establish replacement matching,
disallowance, basis adjustment or deductibility. Leap-day ambiguity and unknown
external/future evidence remain visible, and unsupported term facts keep the
report partial. The bounded generated status does not certify all user intent,
source authenticity, tax treatment or broker lot acceptance. Read the original
request and complete any additional requested analysis without contradicting the
preserved native facts. No output authorizes or blocks native broker actions.
