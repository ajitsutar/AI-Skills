# Fundamental toolkit: explicit calculation contracts

Use `scripts/fundamental_toolkit.py` for offline arithmetic from supplied normalized statements and assumptions. It complements the existing SEC extraction, owner-cash bridge, peer valuation and sector adapters. It does not fetch filings, choose forecasts or certify accounting quality. These are original implementations of published mathematical methods; no third-party source code, prose, tables, model weights or data are bundled.

```powershell
python scripts/fundamental_toolkit.py --input examples/fundamental-dcf.json
python scripts/fundamental_toolkit.py --input examples/fundamental-forecast.json --output forecast-result.json
python -m unittest discover -s tests -p test_fundamental_toolkit.py -v
```

Every input is one JSON object with `operation`, `currency` and `amount_unit`, plus fields below. Numeric inputs must be finite JSON numbers, not strings or booleans. Rates are fractions (`0.10` = 10%). Amounts share one currency/unit; if amounts are millions, `shares` must also be millions so `per_share` is currency per share. All forecasts use full annual periods, cash at year end, and no intermediate rounding. Comparisons use absolute/relative tolerance `1e-9`, not display rounding. Output includes `formula_id`, assumptions and limitations. The CLI creates output files exclusively and refuses an existing output path, including the input path. Missing inputs are never silently zero: ratios return individual unavailable values; incomplete models fail with `INVALID_INPUT` and CLI exit 2.

The `run`/CLI boundary enforces operation-specific and nested schemas. Every listed field for a model is required except the explicitly partial `ratios` inputs. Unknown fields, unsupported timing conventions, extra claim categories, and malformed object rows fail; they are never silently discarded. The only optional top-level annotation is a nonempty `example_context` string. Nested reverse-DCF/Monte-Carlo `valuation` may repeat `currency` and `amount_unit` only when identical to the parent; otherwise they inherit the parent, with no conversion. Put source documents and narrative provenance beside the frozen packet, rather than adding undeclared calculation fields. Per-share outputs explicitly carry `per_share_unit`; DCF/SOTP also echo the share-count scaling convention. Direct individual formula functions are internal arithmetic APIs; use `run` for external packets.

Before use, retain source dates, filing periods, accounting basis, restatements, unit conversions and forecast rationale with the job. Inputs must be known as of the research date. Never treat a forward assumption as an observed filing value. Annual periods must be consecutive, comparable in duration and on a consistent consolidated basis. This toolkit accepts the declared comparability; it cannot independently verify source authenticity.

## Ratios and accounting screens

`ratios`: accepts any subset of `ebit, tax_rate, average_invested_capital, current_assets, current_liabilities, cash, marketable_securities, receivables, interest_expense, revenue, cogs, net_income, average_assets, average_equity, cfo, capex, debt, equity, price, eps, eps_growth_rate`. ROIC uses EBIT after supplied tax divided by average invested capital. Quick assets are cash + marketable securities + receivables (no inventory/prepayments). DuPont uses net margin × turnover × equity multiplier, all with consistent averages. PEG uses P/E divided by EPS growth in percentage points; positive EPS and growth required. Zero interest coverage denominators are unavailable, not infinity. Negative earnings remain negative. Sector interpretation is the caller's responsibility; these are not bank/REIT scorecards.

For liquidity ratios, cash, marketable securities and receivables must be current assets on the same reporting/consolidation basis. If any known nonnegative subset of these components already exceeds supplied total current assets beyond relative/absolute tolerance `1e-9`, current and quick ratios become unavailable with an inconsistency reason. Unrelated margin/profitability calculations remain available when their own inputs support them. Missing components are not filled with zero. Piotroski likewise rejects current assets above total assets.

`piotroski`: `company_type` must be `nonfinancial` or `public_manufacturing`; `annual_periods_comparable: true`. `current` and `prior` each require `beginning_assets, assets, income_before_extraordinary, cfo, long_term_debt, current_assets, current_liabilities, sales, cogs`. Here `long_term_debt` **includes current maturities**. `current.equity_issued` is an explicit boolean recording any equity issuance, not net change in share count. ROA/CFO use beginning assets; leverage uses average assets. Required `turnover_basis` must be `beginning_assets` (paper prose) or `average_assets` (appendix variable definition); the paper is internally inconsistent here, so this choice is explicit in both output and formula ID. Examples select beginning assets. Preserve the selected basis across periods and comparisons. All improvements are strict; equality earns no improvement point. No-issuance earns one point. Current beginning assets must match prior ending assets. Missing fields do not earn zero points; the entire score is unavailable. The original context is high book-to-market stocks, not every issuer. [Piotroski paper, variable definitions](https://www.chicagobooth.edu/~/media/fe874ee65f624aaebd0166b1974fd74d.pdf).

`altman`: only `company_type: public_manufacturing`, with `annual_periods_comparable: true`; requires `assets, working_capital, retained_earnings, ebit, market_equity, total_liabilities, sales`. Uses decimal ratios and coefficients `(1.2,1.4,3.3,0.6,1.0)` in that order, from Altman's 2002 restatement of the original public-manufacturing model. This explicitly uses **1.0**, not the earlier 0.999 sales coefficient. Zones: below 1.81 distress, 1.81–2.99 grey, above 2.99 historical safe zone; not default probabilities or a guarantee. Not valid here for private firms, banks, insurers or REITs. [Altman, Figure 2](https://w4.stern.nyu.edu/finance/docs/WP/2002/pdf/wpa02052.pdf).

`beneish`: the same allowed company types/comparability as Piotroski. Both `current` and `prior` require `sales, cogs, receivables, current_assets, net_ppe, assets, depreciation, depreciation_amortization, sga, current_liabilities, long_term_debt, cash, current_maturities_ltd, tax_payable`. For this model long-term debt excludes current maturities (already in current liabilities); `current_maturities_ltd` is only current maturities of long-term debt included in current liabilities. `depreciation` excludes intangible amortization for DEPI; `depreciation_amortization` includes it for TATA. Uses eight-variable coefficients `-4.840 + .920 DSRI + .528 GMI + .404 AQI + .892 SGI + .115 DEPI - .172 SGAI - .327 LVGI + 4.679 TATA`. TATA uses `(ΔCA−Δcash−ΔCL+Δcurrent_maturities_ltd+Δtax_payable−depreciation_amortization)/assets`, not the later income-minus-CFO variant. Inputs are un-winsorized single-firm values; zero/missing denominators fail instead of adopting the paper's neutral imputations. No universal cutoff, probability or fraud verdict is returned. [Beneish original paper, methods and coefficients](https://diyinvestor.de/wp-content/uploads/2024/09/Beneish-M-Score-paper-1999.pdf).

## Valuation contracts

`wacc`: `market_equity, market_debt, cost_equity, pretax_cost_debt, tax_rate`; market-value weights, after-tax debt cost. Tax shield availability and stable capital structure must be justified before applying WACC. Interest tax deductibility is assumed, not verified.

`dcf`: `cash_flow_type` is `FCFF` with `discount_rate_basis: WACC`, or `FCFE` with `discount_rate_basis: cost_of_equity`. Requires `discount_rate, terminal_growth, annual_cash_flows` (nonempty array), `terminal_next_cash_flow, shares`, and `equity_bridge` containing all four fields `excess_cash, nonoperating_assets, debt, other_claims`, including explicit zeros. Discount rate must be positive and `-1 < terminal_growth < discount_rate`. Terminal next-year cash must be nonnegative and separately supplied with sustainable reinvestment; it is **not inferred from the last annual cash flow**. Present value is all annual CF plus discounted terminal CF/(r−g). FCFF bridge adds excess cash/nonoperating assets and subtracts debt and other claims. FCFE requires debt and other claims zero to prevent double subtraction; any cash addition must be incremental and not already in the CF stream. Terminal value is at the last annual forecast date. Negative explicit-year CF and equity values are retained. [CFA Institute FCFF/FCFE method](https://www.cfainstitute.org/insights/professional-learning/refresher-readings/2026/free-cash-flow-valuation).

`reverse_dcf`: `base_cash_flow` positive, `target_equity_value`, integer `years` 1–100, `growth_low, growth_high` with -1 < low < high, and nested `valuation` with the DCF fields. Replaces its annual cash flow with base × (1+g)^year and terminal cash with last CF × (1+terminal_growth). Solves constant annual CF growth by 100 bisections. Out-of-bracket target fails. This is a one-variable conditional expectation, not simultaneous revenue/margin estimation.

`ddm`: `next_dividend_per_share, cost_equity, growth`; Gordon next-dividend/(r−g), with nonnegative dividend and -1 < g < r. `residual_income`: `opening_book_equity, cost_equity, years` containing `net_income, dividends`, plus `terminal_residual_income_value` **as of final forecast date** (zero explicitly means no residual-income continuation). Book rolls forward by income minus dividends; no issuance, repurchases, OCI or other direct equity changes. Value = initial book + discounted annual (income − r × opening book) + discounted supplied terminal residual-income value. [Damodaran valuation teaching materials](https://pages.stern.nyu.edu/~adamodar/New_Home_Page/valuation/val.htm).

`sotp`: `segments` with unique `id` and supplied `enterprise_value`; `corporate_cost_present_value, excess_cash, nonoperating_assets, debt, other_claims, shares`. Sum segment EV, subtract corporate cost PV, then equity bridge. Segment values may be negative; no silent floor. Caller must eliminate intercompany holdings, duplicate cash, corporate costs already included and overlapping assets.

## Reconciled simplified annual forecast

`forecast`: supported `company_type` is `nonfinancial` or `public_manufacturing`; explicitly set `tax_loss_policy: no_benefit`. Requires `opening_revenue` and `opening` balance sheet with `cash, receivables, inventory, net_ppe, payables, debt, equity`. Assets must equal liabilities plus equity. `years` has 1–100 objects with every field:

`revenue_growth, cogs_fraction, opex_fraction, depreciation, capex, interest_rate, tax_rate, receivables_fraction, inventory_fraction, payables_fraction, new_debt, debt_repayment, equity_issuance, dividends`.

COGS/opex/receivables use revenue fractions. Inventory/payables use COGS fractions. Opex excludes depreciation, separately supplied. Interest uses opening debt; taxes are max(EBIT−interest,0) × tax rate. No tax refund/loss carryforward. Receivables/inventory/payables roll into cash from operations. Debt uses explicit issuance/repayment; equity uses income + issuance − dividends. Insufficient cash fails without a financing plug. Outputs income statement, CFO/FCFF/FCFE, closing balance sheet and cash/balance conservation residuals. FCFF taxes use max(EBIT,0) × tax rate; FCFE uses levered cash taxes. Do not replace the existing detailed financial bridge with this limited model. Leases, deferred taxes, OCI, acquisitions, goodwill and contingent debt are not modeled.

## Monte Carlo scenarios

`monte_carlo`: integer `seed`, `draws` 2–100000, nested DCF `valuation`, and exactly three `distributions`: `discount_rate`, `terminal_growth`, `cash_flow_multiplier`, each with `low, mode, high` for independent triangular draws. Rate support must remain positive and strictly exceed the entire growth support; multiplier lower bound must be nonnegative. The same multiplier scales all explicit-year and terminal CF; it does not change growth or margins independently. Draw order is sorted field name with Python's standard `random.Random(seed)`. Outputs mean and linearly interpolated 5/25/50/75/95 percentiles of equity value. These are assumption-driven scenario quantiles, not calibrated likelihoods or confidence intervals. Preserve seed and Python version for replay.

## Example prompts

- “Using my attached annual filings, calculate Piotroski, original-public-company Altman and Beneish. State the precise formula variants and each input's filing period. Mark missing inputs unavailable; do not invent values or label a company fraudulent from a score.”
- “Build a five-year FCFF valuation for my three-year holding period. Reconcile revenue, margins, reinvestment, financing and cash. Show WACC assumptions, explicit annual cash flows, terminal next-year cash and the bridge to per-share equity.”
- “What constant cash-flow growth does today's price imply under these discount-rate, terminal-growth and balance-sheet assumptions? Use reverse DCF, report the bracket, and explain which assumptions remain fixed.”
- “Compare DDM, residual income and sum-of-parts for this company. Apply each only when the supplied inputs and business model support it; explain the different value bases.”
- “Run a seeded valuation scenario simulation from my explicit triangular assumptions. Show equity quantiles and sensitivity; do not describe the draws as estimated real-world probabilities.”
- “Audit this forecast for cash, debt and balance-sheet conservation before interpreting its DCF. Explain every funding deficit and omitted accounting component.”

Executable fixture inputs are `examples/fundamental-*.json`. `fundamental-golden.json` records selected independently hand-calculated expected outputs and tolerance; tests check those expectations without regenerating expected results from the implementation. Examples are fictional, not investment recommendations.
